# tienkung_planning 扩展指南

面向要改库的工程师。设计文档见 `docs/封装方案.md` v2.1.1；分层与红线不在此重复。
**每一步改动都受 golden 基线守护**：`tests/run_golden.sh` + `tests/golden_compare.py`，
结束时必须 `19/19 ALL PASS` + `BASELINE COMPARE: ALL MATCH`（有意改变行为时，
先重捕基线并在执行记录里说明）。

## 1. 新机型（同族变体）——不写代码

加一份 RobotProfile YAML + 描述四件套（§4.2）：

```yaml
# src/tienkung_planning/robots/<新机型>.yaml
schema: {major: 1, minor: 0}
robot: <新机型>
description:
  urdf: <描述树>/urdf/<机型>.urdf
  srdf: <描述树>/urdf/<机型>.srdf
  kinematics_yaml: ...
  contact_manager_yaml: ...
  mesh_root: <描述树>/meshes
  expected_groups: <组数>
groups: {arm: "{side}_arm", tcp: "{side}_tcp_link", ...}
fingers: {index: {mult: 1.155, upper: 1.41}, ...}
calibration: {right: {center: [...], rotation: [...], seed_arm: [...]}, left: {mirror_of: right}}
```

描述文件内嵌的绝对 `file://` 路径交给重写器处理（`core/profile.py`，
`resolve_description`），**不要**手工改交付件。可运行的完整示例（无 mesh 的
最小机型）见 `tests/fixtures/smoke_bot*` + `tests/test_smoke_nomesh.py`
——该示例随测试走（CI §8.4 第 6 项）。

## 2. 新模式（规划语义）

实现 `ModeStrategy` 协议（`core/mode.py`，结构化鸭子类型，B7）：策略只产出
`ModeConfig`（**字段集即契约**，加字段须走评审），模式差异全部进结构；共享
装配（限位填充 `_finalize_limits`）在策略之外。注册进 demo 的 `MODES` 表。
参考实现：`circle_planning_7axis.py` 的 `TcpModeStrategy/FullModeStrategy/
FixedModeStrategy`。

## 3. 异构 IK 后端

实现签名约定注入 `ModeConfig.ik`（闭包工厂产物）。N5 红线：IK = DLS 主 +
臂 7-DOF LMA 回退的**组合链**，回退前重置 env 状态——新后端替换的是主链，
回退链语义保留。

## 4. 新形状

普通函数即可（§6.2 YAGNI：第二个实现出现前不抽注册表）。形状函数签名 =
采样点序列生成，接进 `plan_shape` 的形状分发。

## 5. 产物契约变更（L0）

`contracts/artifact.py`：加带默认值字段 → `schema_minor +1`（前向兼容，
未知字段不参与 `artifact_hash`）；改/删字段或改语义 → major +1 并同步
`SUPPORTED_MAJOR`。round-trip / 版本拒绝 / 前向兼容用例在
`tests/test_contracts.py`，随改动补用例。

## 6. tesseract 绑定升级

改 `pyproject.toml` 的 `==` 钉版 → 重捕 golden 基线（绑定版本入
manifest）→ 全量比对。绑定坑（TCP 显式、trampoline 继承、坐标系上溯、
StateWaypoint 构造）只收拢在 `core/tess.py`，升级先读其注释。
