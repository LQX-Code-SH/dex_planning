## 三、终审新发现（N1–N10）

### N9（红线，必须先落笔）契约层"仅 numpy"红线在同包分发下会被顶层包入口击穿

**问题**：Q1 决策为"同包默认含 contracts"，其成立前提是"未装 tesseract 的环境 import contracts 成功"。若 `tienkung_planning/__init__.py` 采用常见的 eager re-export（`from .facade import TienKungPlanner`），P-B 侧 `import tienkung_planning.contracts` 会先执行顶层 `__init__` → 连带 import core → tesseract 缺失即 ImportError，红线失效、P-B 无法消费。

**建议（冻结前写死）**：
1. 顶层 `__init__.py` 为空，或采用 PEP 562 惰性 `__getattr__`；`contracts` 子包不得依赖任何上层模块（含顶层包命名空间上的副作用）。
2. §8.4 CI 第 1 项由"L0 不 import 上层"扩为**子进程隔离测试**：在"未安装 tesseract 的裸 venv"中 `python -c "import tienkung_planning.contracts"` 必须成功；eager import 判定用 AST/import 图检查，不用 grep。
3. §11 Q1 决策行补上这条附加条件（现有条件只有 py.typed + 独立 schema_version + import 隔离）。

### N1（中，冻结前）§6.3 `ModeConfig` 键集不全，"取代 cfg dict"的目标未达成

现实现 cfg 的键除 ModeConfig 已列项外还含：`tcp`（tcp 帧，**与 `tip_frame` 不同**）、`joint_names`（完整状态关节名，`positions` 对齐的权威）、`center`/`rotation`（A3 可达性预检与 RViz marker 依赖）、`limits`（全状态 lo/hi，verify 裕度与过渡随机路标回退依赖）、`mode`。见 `793:939:circle_planning_7axis.py`（tcp 模式 `"tcp": TCP_LINK[side], "tip_frame": TCP_LINK[side]`；full/fixed 模式两者不同）。

**建议**：`ModeConfig` 补 `mode_name` / `tcp_frame` / `state_joint_names` / `limits` / `center` / `rotation`，并声明"字段集即契约，新增字段须评审"。

### N3（中，冻结前）"ACM 修复在库内自动做"与"调用后恢复 ACM 快照"会互相抵消

**问题**：§5 把 ACM 纳入快照/恢复范围，而 `TessCollide` 注明"ACM 修复在库内自动做"。若修复是懒触发（首次 check 时算），每次门面调用后恢复 ACM 快照 → 修复结果被丢弃 → **每次调用重算 40×N 采样**（`340:380:circle_planning_7axis.py`），既是性能灾难，也让 §8.3 的"ACM 内容 hash"失去基准。

**建议**：契约写死"ACM 修复**仅在模型构建期执行一次**，其结果即快照基线（此后只读）"；并把 `acm_hash` 作为 `RobotModel` 的公开属性，供 §8.1 步 0 与 §8.3 引用。

### N4（中，冻结前）快照粒度须钉在公开 API 边界，否则性能预算崩

**问题**：现实现的内层 FK 循环每步都写 env 状态（FD 雅可比每列一次 FK）：

```311:319:circle_planning_7axis.py
            J = np.zeros((6, n))
            h = 1e-6
            for i in range(n):
                xp = x.copy()
                xp[i] += h
                pp, Rp = fk(xp)
```

量级：72 航点 × 80 迭代 × (n+1) 次 FK。若"状态不外溢"的上下文管理器落在 IK 内层，单形状 0.2–1.7s 预算无法维持。

**建议**：§5 明确"快照/恢复的粒度 = 能力件与门面的**公开方法调用**，内层私有实现不做快照"；并补一条性能守护（步 0 起记录单形状耗时，超基线 1.5× 报警）。

### N7（中，冻结前）步 0.5 与步 4 职责重叠

**问题**：步 0.5 写"路径外部化"，步 4 写"常量 → RobotProfile YAML + 描述路径重写"。当前绝对路径常量（`83:84:circle_planning_7axis.py`）是同一批代码，两步会重复改、重复回归。

**建议**：切分为——步 0.5：**入口参数化**（描述路径可传入 + 环境变量缺省 + 回归脚本改真 API）；步 4：**重写器实现**（四件套解析、`file://` 重写、URL 编码、缓存）。

### N8（中，冻结前）步 0 基线必须"入口无关"，否则步 0.5 后无法判定漂移

**问题**：步 0 基线由旧入口产出（脚本需先篡改 `sys.argv` 再 import 模块）：

```13:21:tests/regression.py
arm, mode = sys.argv[1], sys.argv[2]
...
sys.argv = _argv
```

步 0.5 改为真 API 调用后，比对若不一致，无法区分"行为漂移"与"入口变化/重建 program 导致的时间戳差异"（§7 已承认时间戳走重建路径需比对确认）。

**建议**：基线文件定义**入口无关判据**：`positions` 逐元素容差、`timestamps` 容差（重建路径可放宽到 1e-6 相对量级并单独标注）、ACM hash、每形状耗时区间、判据阈值（perr/离面/裕度/副指 0.5mm）。

### N2（低，冻结前）§4.1 仍有两个未定义类型 + 一处冗余语义未说明

- `PathErrors`、`SecondaryTrack` 仅以字段类型出现，无定义；`TransitionInfo` 只在注释里列了 3 个字段。L0 冻结要求"每个公开类型有定义 + 序列化映射"。
- `GroupPlan.frozen_waist` 与 `positions` 中腰列**语义冗余**：需说明它记录的是"规划时实际使用的腰值（含镜像后的冻结值）"，用于复现与 P-A 侧对账，而非独立数据源。

### N5（低）§6.2 把 dls/lma 当"两个可替换实现"不准确——代码里是组合链

固定模式（waist free）下是 **DLS 主 → 臂 7-DOF LMA 回退**，且回退前必须把腰状态重置为种子值，否则 LMA 解的是被污染的目标：

```869:885:circle_planning_7axis.py
        def ik_fn(pose, s):
            # 带腰 DLS 为主（腰是冗余自由度，可改善裕度/可达性）；失败退回
            # 臂 7-DOF LMA（腰保持种子值）。robot.ik 的组基座是 waist_pitch_link，
            # 目标位姿换算依赖当前腰状态——DLS 求解过程改写了腰，fallback 前必须
            # 先把腰重置回种子值，否则 LMA 解的是被腰偏移污染过的目标
            sol = dls(pose, s)
```

**建议**：把"回退链 + 回退前状态重置"作为 IK 装配语义写进 §6.3（`ik` 字段含 chain 描述），不要降级为"常量选择"。

### N6（低）§9.1 M1 的"28 对 GJK 结果"缺来源

该数字无本仓库出处（本仓库无 GJK 结果清单）。**建议**改为"由 `traj-check` 脚本产出、可复现的全 mesh 接触对报告，对规格以其输出为准"，并附脚本与输入 hash。

### N10（低，事实补记）资产与版本复验结果

- **版本**：`tesseract_nanobind-main/CHANGELOG.md` 最新条目为 `0.35.0.7`（0.35.0.2 已 yanked），与 §8.2 钉版一致；但**本机实际安装版本未核实**，步 0 应用 `importlib.metadata.version("tesseract-robotics-nanobind")` 实测记录。
- **`meshes_hand/` 未被引用**：本仓库内 URDF/SRDF/yaml 无任何引用（手部 URDF 的 151 处 mesh 全指向 `meshes/`），14MB 属疑死资产——需确认是其他仓库/机型资产并在 profile 中说明归属，否则不应计入打包与文档描述。**`mesh_root` 单键因此足够**（我上一轮担心的双 mesh 目录不成立）。
- **重写范围可精确化**：全仓 `file://` 仅出现在 `tienkung_dex.hand.urdf`（151 处）、`tienkung_dex.urdf`（115 处）、`tienkung_dex.srdf`（2 处，指向两个 yaml）；两个 yaml 自身**不含任何路径**，且全仓无 `package://` 形态。建议 §4.2 把这句话写进重写规则，避免实现者误处理 yaml 内部。
- **SRDF 组与标定来源**：SRDF 共 **22 个组**（2 侧 ×〔arm + 5 指全链 + 5 含腰全链〕）、**0 个 `group_state`** → 标定值只能来自 profile（设计正确）；"组存在性"校验项建议写明"按模板展开 22 组逐一存在"。
