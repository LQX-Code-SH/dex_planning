## 1. 目标与非目标

### 目标

G1 把已验证的规划能力（笛卡尔规划 / 耦合 IK / 腰部冗余 / 多指联动 / TOTG /
碰撞校验 / 过渡轨迹）封装为**可独立安装的 Python 库**，供多项目消费。
G2 支持天工 Dex **机型族**（同族变体零代码、异构机型改配置/适配层）。
G3 消费方**按能力取用**（只用碰撞校验、只用时间参数化都成立），不强迫接受整套管线。
G4 规划与执行解耦：库产出**纯数据产物**，执行由消费方负责。
G5 既有 demo 改造为库的第一个消费者，行为不变，回归兜底。

### 非目标

- 不做运动执行 / 实时控制（消费方的 hand_controller / SDK 链路负责）。
- 不在本库内做 ROS 节点封装（消费方自己包节点；库核心零 ROS 依赖）。
- 不承诺实时硬性指标（现有 DLS/Descartes 是离线/准实时量级）。
- 第一版不发布 PyPI（消费方式见 §8.2：先 submodule，稳定后 git 直装）。

## 2. 消费者画像（通用性依据）

| 画像 | 需要什么 | 不需要什么 | 对设计的约束 |
|---|---|---|---|
| P-A 离线规划项目（如 Biview-Manipulation） | 抓取位姿/航路点规划、TOTG、精确碰撞校验、腰+臂联合解 → 产物给在线执行 | 实时循环、RViz | 产物契约一等公民；解释器可隔离（CLI 可用） |
| P-B 在线执行项目（真机节点） | 零重依赖的**契约层**（产物 schema、手指耦合表、状态约定） | tesseract/pinocchio | 契约层仅 numpy+标准库（红线） |
| P-C 同族机型变体（不同灵巧手/臂长/自由度微差） | 换 YAML 即用 | 改源码 | 机型=配置；描述四件套+路径重写（§4.2） |
| P-D 异构机型（非天工臂、不同 IK 后端） | 替换 IK 后端 / 部分能力件 | 接受天工假设 | IK/时间参数化可注入；天工特有假设集中且可绕过 |
| P-E 研究/仿真用户 | 原语级 API（FK/IK/碰撞/限位）自行组装 | 完整管线 | 能力件互相独立、入出参纯 numpy |

```
├────────────────────────────────────────────────────────┤
│ L2 核心层:                                              │

  ① L0 不 import 本库任何上层  ② tesseract 仅出现在 tess.py
```

分包（Q1 已决策：同包默认含 contracts，不拆独立发行）：

```
tienkung-planning
├── tienkung_planning.contracts      # L0：纯 dataclass/numpy，带 py.typed 与独立 schema_version
├── tienkung_planning.core           # L1+L2：tesseract 依赖在这里
├── tienkung_planning.facade         # L3
├── tienkung_planning.apps           # L4：CLI
```

**顶层入口红线（N9，冻结前写死）**：`tienkung_planning/__init__.py` 为空，
或仅用 PEP 562 惰性 `__getattr__`——**禁止 eager re-export**（否则未装
tesseract 的 P-B 侧 `import tienkung_planning.contracts` 会先执行顶层包、
连带 import core 而失败，"仅 numpy"红线被击穿）。`contracts` 子包不得依赖
任何上层模块，包括顶层包命名空间上的 import 副作用。

## 4. L0 契约层（冻结前置条件：B2、B8 修订即本节）

### 4.1 轨迹产物契约（完整定义，取代 v1.x 草案）

坐标系/单位/表示/时间基准见 §4.4（所有字段默认遵循之）。

```python
@dataclass
class GroupPlan:                       # 一条链（一臂）的规划结果
    group_name: str                    # 如 "right_arm" / "right_arm_waist_index"
    joint_names: tuple[str, ...]       # 与 positions 列对齐（唯一权威表示）
    positions: np.ndarray              # (N, dof) rad；load 后置只读
    timestamps: np.ndarray             # (N,) s，自轨迹起点
    time_source: Literal["totg", "uniform"]
    tip_frame: str                     # 跟踪的末端链接
    ideal_path: np.ndarray             # (N, 3) m，pelvis 系目标路径
    err_stats: PathErrors              # 主指 max/avg 位置误差(mm)、离面(mm)
    secondary: dict[str, SecondaryTrack] = field(default_factory=dict)
        # 多指副指随动记录：finger -> SecondaryTrack
    frozen_waist: np.ndarray | None = None
        # 【W2 后恒为 None】腰是两臂共享的同一组物理关节值，已逐帧落在 positions
        # 的腰列里（两臂腰列一致），该字段不再有独立信息 → 记账退化为 None。
        # 历史语义：曾记录"该链被冻结的腰值"（both+free 时右臂解**经镜像后**的
        # 冻结值）；镜像口径已废弃——物理腰只有一套，镜像注入造成 109 mm 执行
        # 误差（见 §6.2 W1/W2 修订）。
        # 契约影响：字段类型不变（Optional[object]）且本例本就被声明为"冗余记账
        # 字段、非独立数据源"，消费侧可从 positions 腰列推导 → **不参与 load 拒绝
        # 判定，schema_minor 不升版**；仅记变更说明（§4.5/§10）。

@dataclass
class PlanArtifact:
    schema_version: int                # 契约 major 版本（§4.5：唯一参与 load 拒绝判定）
    kind: Literal["shape", "transition"]
    profile_id: str                    # 机型 profile 标识
    profile_hash: str                  # profile 内容 hash——过渡回退/复现性依赖
    meta: PlanMeta
    groups: dict[str, GroupPlan]       # "right"/"left" -> …
    schema_minor: int = 0              # minor 版本（§4.5：仅新增带默认值字段时 +1；
                                       # 置于默认值区以保 dataclass 字段顺序合法）
    # shape 类：
    waypoints: dict[str, np.ndarray] | None = None   # per-group 目标路径(M,3)
    # transition 类（v1 缺失项，补齐）：
    transition_info: TransitionInfo | None = None    # source_artifact_hash、
                                                     # target_artifact_hash、
                                                     # 关节限位 lo/hi（随机路标回退所需）

@dataclass
class PlanMeta:
    library_version: str
    created_at: str                    # ISO8601 UTC
    mode: str                          # full/fixed/tcp
    options: dict                      # PlannerOptions 序列化（arm/waist/fingers/…）

@dataclass
class PathErrors:                      # 路径跟踪误差统计
    max_mm: float                      # 目标路径最大位置误差
    avg_mm: float
    max_offplane_mm: float             # 离面误差（形状平面法向分量最大值）

@dataclass
class SecondaryTrack:                  # 副指随动记录（B2 刚体联动语义）
    tip_frame: str                     # 副指尖链接名
    delta: np.ndarray                  # (3,) 相对主指尖的世界系常量偏移 (m)
    max_err_mm: float                  # 随动误差（验证口径 <0.5mm）

@dataclass
class TransitionInfo:                  # kind="transition" 时必填
    source_artifact_hash: str          # 起点 shape 产物
    target_artifact_hash: str          # 终点 shape 产物
    joint_limits: tuple[np.ndarray, np.ndarray]   # (lo, hi)，随机路标回退所需
```

**表示与不变量**（回应 B8-3/4）：
- 唯一权威表示 = `joint_names` 元组 + `positions` 数组；`{"joint_name": rad}` 字典
  只是派生访问器 `GroupPlan.q(i) -> dict`，不参与序列化。
- ndarray **不承诺不可变**（frozen 只防重绑定）——load/save 路径统一 `arr.setflags(write=False)`
  置只读；库内构造同样执行。需哈希/缓存键时用显式 `artifact_hash(art)`（内容 hash），
  不用对象 hash。
- 读写 API：`save(path)`（npz+json 打包或 zip——格式二选一在步 0 前定死，B5）、
  `PlanArtifact.load(path, max_schema=None)`——拒绝判定**只看 major**：产物
  `schema_version` 高于库支持即抛 `ContractVersionError`（拒绝过新而非静默
  错读）；major 不高于库支持时，更高 `schema_minor` 携带的未知字段**安全忽略**
  （前向兼容，§4.5），且未知字段不参与 `artifact_hash`（§4.6）。

### 4.2 RobotProfile 契约（机型 = 配置；回应 B2/B3/D3/D5）

```yaml
profile_version: 1
robot: {name: tienkung_dex, root: pelvis}
sides: [right, left]
groups:                                  # 组命名约定显式化
  arm: "{side}_arm"
  full: "{side}_arm_{finger}"            # 注意：组名只由**主指尖**决定（多指副指仅验证）
  waist: "{side}_arm_waist_{finger}"
  tcp: "{side}_tcp_link"
fingers:
  index: {mult: 1.155, upper: 1.41}
  thumb: {mult: 1.0, upper: 1.03, mc_joint: "{side}_thumb_metacarpal_joint"}
coupling: {distal_of_prox: true}
seed_search: {strategy: mirror_sign_enum, tol_mm: 5, tol_mrad: 5}
calibration:
  right: {center: [...], rotation: [...], seed_arm: [...]}
  left:  {calibrate: mirror_sign_enum, target: mirror(right)}
  # ↑ 不是纯数学镜像：2^7 符号枚举 + 限位过滤 + FK 残差择优（URDF 左右不严格对称，
  #   实测残差 ~1mm/0.003rad）；加载校验项：残差超阈 → 告警，超硬阈 → 拒绝加载
description:                              # 四件套（B2：缺一不可）
  urdf: ...
  srdf: ...                              # srdf 内还引用 ③④ 两个 yaml
  kinematics_plugins: ...                # tienkung_dex_plugins.yaml
  contact_managers: ...                  # contact_manager_plugins.yaml
  mesh_root: ...                         # 可指向库外路径
limits: {velocity: from_urdf}             # TOTG 依赖 URDF 速度限位（§7 边界）
```

**描述文件路径重写规则（B2 核心补充，`mesh_root` 生效的前提）**：
- 当前 URDF/SRDF 内是本机绝对 `file://` 路径且含**未 URL 编码的中文文件名**
  （如 `腕部相机右.STL`）。
- 重写范围实测（N10）：`file://` 仅出现在 `tienkung_dex.hand.urdf`（151 处）、
  `tienkung_dex.urdf`（115 处）、`tienkung_dex.srdf`（2 处，指向两个 yaml）；
  **两个 yaml 自身不含任何路径，全仓无 `package://` 形态**——重写器无需处理
  yaml 内部。
- 库在 `Robot.from_files` **之前**执行重写：把四件套内所有 `file:///abs/path`
  前缀替换为 `description` 各键解析出的实际位置，mesh 路径同时替换 `mesh_root`；
  中文/空格路径做 URL 编码。
- 重写产物写入临时目录（生命周期 = Robot 实例；`TIENKUNG_PLANNING_CACHE_DIR`
  环境变量可指定持久缓存，按 (文件内容 hash, mesh_root) 键缓存）。
- 加载校验（fail-fast）：四件套齐全、组存在性（按模板展开 **22 组**逐一存在；
  SRDF 无 `group_state`，标定值只能来自 profile）、校准点 FK 冒烟、限位字段存在。

### 4.3 异常层级

```
TienKungPlanningError
├── ProfileError            # 机型配置缺失/不合法/校准残差超阈
├── ContractVersionError    # 产物 schema major 版本过新（§4.1/§4.5）
├── UnavailableError        # 能力前置条件缺失（如无 URDF 速度限位 → TOTG 不可用，§7）
├── UnreachableError        # 预检/IK 判不可达（附建议）
├── CollisionError          # 显式扫描发现碰撞（附对与帧号）
└── PlannerError            # 规划器内部失败（附原因分类码）
```

### 4.4 单位 / 坐标系 / 姿态 / 时间契约（B8-7，P-A↔P-B 对接的坑源）

| 项 | 契约 |
|---|---|
| 坐标系 | 一切位置/路径为 **pelvis（根链接）系**；无工作 frame 换算暴露给消费方 |
| 单位 | 位置米、角度弧度、时间秒 |
| 姿态 | 库与产物内一律 **3×3 旋转矩阵**（json 侧行主序 9 元素）；四元数只存在于 demo/RViz 展示层 |
| 时间 | `timestamps[i]` = 自轨迹起点秒（TOTG `time_from_start`；uniform 回退为线性） |
| 侧语义 | `both` 模式右侧为基准、左侧为镜像派生；副指 delta 为**世界系常量**（B2 语义） |

### 4.5 版本策略

`schema_version`（major）与 `schema_minor` 各自独立于包版本递增，语义分工如下
（消解 v2.1 中 §4.1"高于即拒"与 §4.5"旧库可读"的表述冲突）：

- **minor+**（`schema_minor` +1）：仅允许**新增带默认值字段**。旧库读新产物：
  major 不高于库支持 → 正常加载，未知字段安全忽略（前向兼容）；新库读旧产物：
  缺省字段取默认值（后向兼容）。
- **major+**（`schema_version` +1，`schema_minor` 归零）：删改字段/语义变更。
  产物 major 高于库支持 → `load` 抛 `ContractVersionError` 显式拒绝。

兼容性由"序列化往返测试 + 版本拒绝测试（含 minor 前向兼容用例：旧库加载带
未知字段的新 minor 产物）"守护（§8.3）。

### 4.6 内容 hash 契约（A3）

`artifact_hash` / `profile_hash` / `acm_hash` 被 golden 基线、B4 缓存键、
`TransitionInfo.source/target_artifact_hash` 直接依赖，必须**同内容即同值**。
算法钉死（实现于 L0 `contracts`，除 numpy 外零依赖）：

- **规范化**：浮点 ndarray 统一 `np.ascontiguousarray(a, dtype=np.float64)` 后取
  原始字节；整型/布尔显式定 dtype；字符串一律 UTF-8。
- **拼接**：按 dataclass **字段声明顺序**逐字段拼 `字段名 + 类型标签 + 8 字节
  长度前缀 + 载荷`（长度前缀消解分隔符与嵌套歧义，覆盖
  `tuple[np.ndarray, np.ndarray]` 等结构）；可选字段（`| None`）以 1 字节
  存在性标记参与。**禁止** `str(dict)`/`repr`（dict 顺序与 numpy 打印精度
  均不稳定）。
- **摘要**：SHA-256，hex 输出。
- **参与字段**：
  - `artifact_hash(art)`：`PlanArtifact` 全部语义字段，排除 `meta.created_at`
    （时间戳非确定）；更高 `schema_minor` 携带的未知字段不参与（同语义内容
    → 同 hash）。
  - `profile_hash`：profile 语义字段 + 四件套**文件内容** hash（键排序的规范化
    序列化），**不含本机路径**（同内容跨机器可复现）。
  - `acm_hash`：ACM 允许对集合按 link 名对**排序后**序列化再哈希（消除容器
    内部顺序差异）。
- **稳定性边界**：承诺"同库版本 + 同内容 → 跨平台同值"；numpy/tesseract
  升级后须先重算 golden 基线中的全部 hash 再比对（步 0 起回归显式断言）。

## 5. L1 防腐层（tesseract 唯一居所）

```
TessRobot:  from_description(desc) · set_joints(names, values) · fk(links) -> {link: (p, R)}
            jacobian(group) · joint_limits(group) · active_links()
TessCollide: check(states) -> list[ContactPair]   # ACM 修复仅在模型构建期执行一次（见下）
TessPlanner: descartes(program) · totg(program)
```

线程与状态契约（写进每个 API docstring；回应 B5）：

- **非线程安全**：tesseract env 是有状态单例，一个 TessRobot 实例只归一个线程；
  多线程 = 多实例。
- **状态不外溢**：门面调用结束后恢复调用前快照（上下文管理器实现）。
  快照范围**显式定义**为：全关节值（含 other_pos 涉及的手指关节）+ ACM + 碰撞裕度
  + active links——四者都是 env 全局态，一并快照/恢复。
- **快照粒度（N4，冻结前钉死）**：快照/恢复只发生在能力件与门面的**公开方法
  调用边界**；内层私有实现（IK 的 FD 雅可比逐列 setState、加密循环等）不做
  快照——否则 72 航点 × 80 迭代 × (n+1) 次 FK 的量级下，单形状 0.2–1.7s
  预算必崩。性能守护：步 0 起记录单形状耗时，**超基线 1.5× 报警**。
- **ACM 修复时机（N3，冻结前写死）**：ACM 修复**仅在模型构建期执行一次**，
  其结果即快照基线（此后只读）——若懒触发（首次 check 时算），会被"调用后
  恢复 ACM 快照"抵消，每次调用重算 40×N 采样。`RobotModel.acm_hash` 为公开
  属性，供 §8.1 步 0 基线与 §8.3 缓存键引用。
- **会话状态例外**：`both + waist free` 的冻腰注入（右臂解 → 左臂读取）是**编排器
  持有的跨调用会话状态**（存 DualArmCoordinator，不存 env）——不依赖快照恢复兜住，
  编排器在每个形状规划开始时显式注入、结束时丢弃。

## 6. L2 核心层

### 6.1 PlanPipeline（模板方法；B1 修订：顺序与碰撞归属按实现纠正）

```
interpolate(targets)        # 笛卡尔航点先加密（阈值略大于航点间距，避免插值位姿无解）
solve_cartesian(interpolated, ik)   # Descartes/WarmStart 采样求解；碰撞校验主力①
time_parameterize(results)          # 策略链：TOTG → uniform（回退链显式化）
verify(Q, targets, mode)            # 精度 + 副指随动钩子；显式后置扫描②按需
```

**碰撞校验两分法**（B1 核心）：
- ① **规划器内部状态/边校验**（Descartes 内建，依赖 ACM + margin）——单臂形状链路
  的主力，`fix_allowed_collisions` 不做则任何位形都报碰撞。库不在此之外重复加全量
  扫描（会改变 golden 基线）。
- ② **库显式后置扫描**——只用于过渡轨迹逐点、双臂互碰、副指随动等管线外场景
  （对应现实现 522:538 / 665:697 的行为）。

`plan_shape / plan_transition` 共用此管线（过渡 = 关节直线特例）；
手指语义是 ModeStrategy/verify 钩子，不是新管线（B2 教训固化）。

### 6.2 策略注册表（D8 修订：YAGNI 收敛）

**第一版只保留有真实多实现的两个注册表**：

| 注册表 | 已有实现 |
|---|---|
| `MODES` | full / fixed / tcp |
| `WAIST_POLICIES` | owned（腰归右臂，**仅作协商初值**）/ negotiated（W2 实际形态：两臂共享物理腰 + 失败帧协商）；mirror-frozen **已废弃**（镜像注入造成 109 mm 执行误差） |

`SHAPES`（4 个）、IK 装配（N5：DLS 主 + 臂 7-DOF LMA 回退的**组合链**，属
§6.3 `ik` 字段的装配语义，非两个独立可替换实现）、`TIME_PARAMS`（totg/uniform）、
`SEED_SEARCH`（1 个）第一版用普通常量/工厂函数——**第二个真实实现出现时再抽

**【W1 修订（2026-09-17 已实施）】** `--waist` 由二值（fixed/free）改三级：
`fixed`（腰全锁，默认）/ `free`（只放 yaw = `waist_33`，水平旋转、风险低）/
`all`（yaw+roll+pitch，即原 free 语义，弯腰抓取等复杂任务才需要）。非活跃腰
**不进变量空间**（真降维）：原"变量必须是组状态前缀"的断言放宽为"组状态保序
子集"，warm-start 种子改按变量在状态中的位置索引投影，状态展开按关节名写回。
`GroupPlan.frozen_waist` 仍为组链顺序的**全量 3 维**（契约字段不变），冻结腰注入
统一经 `frozen_waist_from_vars`（活跃腰散回全量后镜像），6 处消费方不再各自切片。
基线迁移：`*-free*` → `*-all*`（npz + entries + manifest 键）并逐元素复现
**ALL MATCH**，新增 yaw-only 组合基线。实测 yaw-only 腰幅度 0.143 rad、perr
0.0004 mm，优于 all 的 0.436 rad（roll 顶 ±25° 限位）、0.0028 mm——印证"慎动腰"
不牺牲精度。**W1 只解除解锁粒度问题，不修复 W2（both 时左臂冻结腰与物理腰共享
的矛盾）**。

### 6.4 DualArmCoordinator（双臂编排，L2 无 ROS）

侧规划顺序（腰持有侧先）、冻腰注入（WaistPolicy，会话状态存此）、双臂互碰校验
（显式扫描②）、失败联动（一侧失败 → 另一侧按策略放弃/告警）。单臂 = 平凡实现。

已知限制（B7，继承现实现 `check_dual_collision` 的 `min(len)` 行为，为保 golden
基线不变而照搬）：两臂帧数不一致时互碰校验仅覆盖前 `min(N_left, N_right)` 帧，
较长一侧尾部不校验——消费方需自行保证两侧同源时间轴，或显式请求补齐校验。

## 13. 消费指南（新项目如何使用，§8.2 Q5 决策的落地说明）

**核心回答：不是继承。** 设计上刻意避免"继承 Planner 基类再用"——模板方法
（§6.1）已把变化点收敛为策略注册与配置注入，继承会绑死实现细节、升级即断。
对外只有两个扩展面：`from_profile` 工厂 + Protocol 协议。

### 13.1 四种典型用法

> **实现状态（v0.2，2026-09-16）**：①②的门面已落地
> （`tienkung_planning.facade`：`TienKungPlanner`/`PlannerOptions`/`CheckReport`/
> `CollisionApi`/`TimeParamApi`/`TimedTrajectory`；测试 `tests/test_facade.py`，
> §13.1 用法①②逐字可跑）。③④可用：契约层 `contracts`（`PlanArtifact.load`，
> 裸 venv 可 import）与 CLI 读产物照本节用法。产物格式（B5 决策）：
> `.traj` = ZIP（`meta.json` + `arrays.npz`）。B6 决策：一实例一 env 一线程，
> `from_profile` 时装载、无全局缓存；`TienKungPlanner.plan_transition` 仅接受
> 同实例产物（profile_hash + 关节表校验）。已知事实：demo `_scan_collision`
> 的 ACM 过滤方向与其 docstring 相反（待修项）；同手相邻指在 2cm 裕度下
